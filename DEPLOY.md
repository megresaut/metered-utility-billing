# Deploying Metered (beta)

Target: a **small pilot (10–20 customers)**. At that volume load is trivial — a
single container handles it. This guide stands up the safe, hostable beta floor.

Architecture in production:

```
  Browser ──▶ Vercel (React frontend, /api proxied) ──▶ Render (Go API + worker) ──▶ Render Postgres
                                                              │
                                                              └── persistent disk /data (PDFs, 2FA handoff)
```

The API image (`Dockerfile`) runs **one Go process = API + scrape worker +
scheduler**, shelling out to Python/Playwright. It needs a persistent process
and a real browser, so it runs on **Render (container)**, not serverless.

---

## 1. Prerequisites

- A Render account and this repo pushed to GitHub/GitLab.
- A Vercel account (for the frontend).
- An OpenRouter API key (used for AI bill extraction; OpenAI-compatible).
- Generate two secrets locally:
  ```bash
  openssl rand -hex 32   # → JWT_SECRET (Render can also auto-generate this)
  openssl rand -hex 32   # → CRED_MASTER_KEY (MUST be 64 hex chars)
  ```

## 2. Deploy the API + database (Render)

1. In Render: **New → Blueprint**, point it at this repo. Render reads
   `render.yaml` and provisions the `metered-api` web service (with a 1 GB disk
   at `/data`) and the `metered-db` Postgres (with automated daily backups).
2. On first deploy, set the `sync: false` secrets in the service's
   **Environment** tab:
   - `CRED_MASTER_KEY` — the 64-hex key you generated. **Back this up.** Losing
     it makes every stored portal credential undecryptable.
   - `OPENROUTER_API_KEY` — your OpenRouter key. (Optionally `OPENROUTER_MODEL`
     to pick a cheaper/pricier extraction model; defaults to `openai/gpt-4o-mini`.)
   - `CORS_ALLOWED_ORIGINS` — your frontend origin (e.g.
     `https://app.yourdomain.com`). Required in production even if you use the
     proxy in step 3.
   - `JWT_SECRET` is auto-generated by Render; `DATABASE_URL` is wired from the
     database automatically.
3. Redeploy. Migrations run automatically on boot. Confirm health:
   `curl https://<your-render-url>/api/health` → `{"status":"ok"}`.

> The server refuses to boot in production (`APP_ENV=production`) if `JWT_SECRET`
> is the dev default, `CRED_MASTER_KEY` is missing, `DATABASE_URL` uses
> `sslmode=disable`, `OPENROUTER_API_KEY` is missing, or `CORS_ALLOWED_ORIGINS`
> is empty. This is intentional — see `config.Validate()`.

## 3. Deploy the frontend (Vercel)

Create a **separate Vercel project** rooted at `web/` (distinct from the public
`VITE_DEMO=1` demo). Build with `VITE_DEMO` **unset** so it talks to the real
API. Add a proxy rewrite so the browser stays same-origin (simplest; sidesteps
CORS entirely). In the beta frontend's `vercel.json`, put the `/api` proxy
**before** the SPA fallback:

```json
{
  "rewrites": [
    { "source": "/api/:path*", "destination": "https://<your-render-url>/api/:path*" },
    { "source": "/((?!assets/|favicon.svg).*)", "destination": "/index.html" }
  ]
}
```

(Alternatively, call the API's absolute URL directly and rely on
`CORS_ALLOWED_ORIGINS` — but the proxy is less error-prone for beta.)

## 4. Onboard a pilot customer (manual — fine at this scale)

There is no self-serve signup. Use the admin CLI via Render's **Shell** tab
(or `render ssh`):

```bash
/app/admin create-org  --name "Acme Property Management"
/app/admin create-user --org-id <id> --email admin@acme.com --password <temp>
# password resets:
/app/admin reset-password --email admin@acme.com --password <new>
```

Then the customer signs in, adds properties + utility accounts (real portal
credentials to enable auto-scrape), and uploads/imports bills.

## 5. 2FA handoff (Aquarion, WinWaste — manual for beta)

When one of these portals emails a login code mid-scrape, the worker logs the
path it's waiting on under `/data/handoff/<provider>/2fa_code.txt`. Drop the
code there (via Render Shell) while the scrape waits. Automating this is a
post-beta item.

## Tenant isolation (RLS)

Postgres row-level security (`003_rls.sql`) scopes every request's queries to
the caller's org, as defense-in-depth behind the app-layer `WHERE org_id`
filters. **It only enforces if the app connects as a non-superuser role** — the
default on Render (your DB role owns its objects but is not a Postgres
superuser), so no action is needed there. Do not grant the app role SUPERUSER or
BYPASSRLS. The app connects with two pools (request-scoped + a trusted bypass
pool for the worker/scheduler/login/migrations); this is automatic.

## 6. Backups & secrets hygiene

- **Postgres**: Render's paid tier takes automated daily backups. Verify a
  restore once before you rely on it.
- **`CRED_MASTER_KEY`**: store a copy in your password/secret manager. It is the
  only key that decrypts customer portal credentials.
- Never commit `.env`. Rotate `JWT_SECRET` only when you're ready to log
  everyone out (it invalidates all sessions).

## What's deliberately deferred past this beta

Tracked separately, not required to onboard 10–20 pilots: Postgres row-level
security / per-tenant key rotation (strongly recommended fast-follow — see the
tenant-isolation task), a self-serve onboarding UI, a 2FA-code submit UI,

disk suffices for a single instance), and Stripe/billing. See the task list.
